Multivariate Linear Regression

Hour 2–4 · From one input feature to many

From One Feature to Many Hour 2

Where we left off. Last week's model predicted an exam score from a single input: hours studied. But almost nothing real depends on just one factor — a house's price depends on its size and number of bedrooms and location and age. Multivariate (or "multiple") Linear Regression simply extends the same straight-line idea to handle several input features at once, each with its own weight.

y = w1*x1 + w2*x2 + w3*x3 + ... + b
# y = predicted output (e.g. house price)
# x1, x2, x3... = input features (size, bedrooms, age...)
# w1, w2, w3... = weights — how much each feature matters
# b = the intercept/bias, same role as before

Training still means the exact same loop from last week — guess, measure error with the cost function, adjust with the optimizer, repeat — just now adjusting several weights instead of just one m.

Video: "Multiple Regression, Clearly Explained!!!" — StatQuest with Josh Starmer

Why This Needs Vectorization — the Feature Matrix Hour 3

With many features and many training examples, writing out w1*x1 + w2*x2 + ... by hand for every row gets unwieldy fast. Instead, we organize all the features into a matrix (a 2D NumPy array from Week 3 — every row is one training example, every column is one feature) and all the weights into a vector, so the entire prediction step becomes a single matrix multiplication:

import numpy as np

# each row = one house; columns = [size_sqft, bedrooms, age_years]
X = np.array([
    [1200, 3, 10],
    [1500, 4, 5],
    [800,  2, 20]
])
weights = np.array([50, 10000, -200])   # one weight per feature
bias = 30000

predictions = X @ weights + bias   # @ is matrix multiplication — all 3 predictions computed at once!
print(predictions)
Connecting back to Week 3–4 X @ weights is the vectorized version of exactly what last week's unvectorized loop did with for i in range(n): — just extended to handle multiple features per example. This is the same "loops vs. vectorization" upgrade you practiced last week, now shown in its full, general form.

Feature Scaling — A Practical Necessity Hour 4

A new problem that appears with multiple features. Imagine one feature is "house size" (values in the thousands, like 1500) and another is "number of bedrooms" (values like 3). Gradient Descent's step size interacts badly with this mismatch — a learning rate that works for bedrooms will be far too small or too large for size, making training slow or unstable. Feature scaling (also called normalization or standardization) rescales every feature to a similar range before training, fixing this.

# standardization: subtract the mean, divide by the standard deviation (Week 2!)
X_mean = X.mean(axis=0)
X_std = X.std(axis=0)
X_scaled = (X - X_mean) / X_std   # broadcasting from Week 3, applied here
print(X_scaled)
Common mistake Forgetting feature scaling is one of the most common reasons a from-scratch Gradient Descent implementation seems to "not work" — it isn't broken, it's just struggling with wildly different feature scales pulling the learning rate in different directions.

Polynomial Regression

Hour 1–4 · Fitting curves, not just straight lines

When a Straight Line Isn't Enough Hour 1–2

The limitation Linear Regression can't escape. No matter how you tune m and b, a straight line can only ever be... straight. But plenty of real relationships genuinely curve — a car's stopping distance grows faster than proportionally with speed; plant growth often follows a curved, not straight, pattern over time. Forcing a straight line onto obviously curved data leaves the model "underfit" — systematically wrong in a predictable, curved pattern.

The trick Polynomial Regression uses. Instead of inventing a whole new algorithm, we simply add new, transformed features — x², x³, and so on — as extra columns fed into the exact same Linear Regression machinery you already know. The model is still "linear" in its weights (each weight still just multiplies one feature and adds up); it's the relationship to the original x that becomes curved.

y = w1*x + w2*x² + w3*x³ + b
# still just weights multiplied by features and summed —
# only difference from Day 1: some of the "features" are powers of the same original x

Video: "Polynomial Regression Explained | Machine Learning for Beginners"

Implementing It Hour 2–3

import numpy as np

x = np.array([1, 2, 3, 4, 5])
y = np.array([2, 8, 18, 32, 50])   # clearly curved, not a straight line

# manually build polynomial features up to degree 2
X_poly = np.column_stack([x, x**2])   # now we have TWO features: x and x²
print(X_poly)

# from here, training is IDENTICAL to Day 1's multivariate regression —
# same cost function, same gradient descent, just with these engineered features

In practice, you'll usually use a helper rather than building these columns by hand:

from sklearn.preprocessing import PolynomialFeatures

poly = PolynomialFeatures(degree=2)
X_poly = poly.fit_transform(x.reshape(-1, 1))
print(X_poly)   # columns: [1, x, x²] — includes the bias column automatically

Choosing the Right Degree — Underfitting vs. Overfitting Hour 4

The central tension of this topic. A degree-1 polynomial is just the straight line from before — too simple for curved data (underfitting: the model is too rigid to capture the real pattern). But cranking the degree very high (say, degree 15) lets the curve wiggle through literally every training point perfectly — which sounds great, but actually means the model has memorized noise specific to this exact training data rather than learning the true underlying pattern (overfitting). An overfit model performs beautifully on data it's already seen and poorly on new, unseen data — the opposite of what you actually want.

The rule of thumb to remember Higher polynomial degree = more flexible, but more prone to overfitting. The right degree is usually the simplest one that captures the real shape of the data — you'll learn formal ways to choose this (train/test splits, cross-validation) explicitly in Week 6's Testing & Evaluation material.

Logistic Regression — Binary Classification

Hour 1–4 · From predicting numbers to predicting categories

Why Linear Regression Fails for Classification Hour 1

The genuine turning point of this week. Suppose you want to predict "will this student pass (1) or fail (0)?" from hours studied. You could try feeding pass/fail (0 or 1) into last week's Linear Regression — but a straight line can shoot off to 3.7 or −2.1, which makes no sense as a probability. We need an output that's always squeezed between 0 and 1, no matter how extreme the input is. Logistic Regression is Linear Regression's answer to exactly this problem, despite the slightly confusing name — it's actually a classification algorithm.

Video: "StatQuest: Logistic Regression" — StatQuest with Josh Starmer

The Sigmoid Function — Squeezing Any Number Into 0–1 Hour 2

The fix is a single, elegant mathematical function called the sigmoid (or "logistic") function. Whatever number the linear part w*x + b produces — no matter how large or negative — the sigmoid function squashes it into a smooth S-shaped curve that always stays between 0 and 1, which we then interpret directly as a probability.

sigmoid(z) = 1 / (1 + e^(-z))

import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

print(sigmoid(-10))   # ≈ 0.00005 — very close to 0
print(sigmoid(0))       # exactly 0.5 — the "undecided" midpoint
print(sigmoid(10))      # ≈ 0.99995 — very close to 1

The full model: compute the familiar linear combination, then squash it through sigmoid:

z = w * x + b                  # same linear combination as Linear Regression
probability = sigmoid(z)        # now guaranteed to be between 0 and 1

# applying a decision threshold to get an actual class label
predicted_class = 1 if probability >= 0.5 else 0

A Different Cost Function — Why MSE Doesn't Work Here Hour 3

Using last week's Mean Squared Error cost function on a sigmoid output creates a bumpy, unreliable landscape for Gradient Descent to search (mathematically, it's no longer a smooth, single-valley bowl). Logistic Regression instead uses a purpose-built cost function called log loss (or "binary cross-entropy"), which heavily penalizes confident, wrong predictions:

Cost = -(1/n) * Σ [ y*log(p) + (1-y)*log(1-p) ]
# y = the true label (0 or 1)
# p = the model's predicted probability
# if the true answer is 1 but the model confidently predicted p=0.01,
# log(p) is a huge negative number — the cost function punishes this heavily
The intuition, without the formula Log loss says: "being unsure (predicting 0.5) is a small, forgivable mistake; being confidently wrong (predicting 0.99 for the wrong class) is a very large, heavily punished mistake." This shapes training to prefer well-calibrated, honest probabilities.

Training with Gradient Descent — Same Loop, New Pieces Hour 4

x = np.array([1, 2, 3, 4, 5, 6, 7, 8])
y = np.array([0, 0, 0, 0, 1, 1, 1, 1])   # pass (1) / fail (0)

w, b = 0.0, 0.0
learning_rate = 0.1
epochs = 2000
n = len(x)

for epoch in range(epochs):
    z = w * x + b
    p = sigmoid(z)              # predicted probabilities, vectorized
    error = p - y                 # same "prediction minus actual" pattern as Week 4

    w_gradient = (1/n) * np.sum(error * x)
    b_gradient = (1/n) * np.sum(error)

    w = w - learning_rate * w_gradient
    b = b - learning_rate * b_gradient

print(f"Trained model: sigmoid({w:.2f}x + {b:.2f})")
print(sigmoid(w * 4.5 + b))   # predicted probability of passing at 4.5 hours studied
The pattern to notice This is structurally identical to last week's vectorized Gradient Descent loop — guess, compute error, compute gradient, step downhill, repeat. Only the hypothesis function (sigmoid instead of a raw line) and the cost function (log loss instead of MSE) changed. This reuse of the exact same training loop is the single most important pattern in classical ML — you'll see it again and again.

Logistic Regression — Multiclass Classification

Hour 1–4 · From 2 classes to many, with Softmax

The Problem With Just Two Classes Hour 1

What if there are more than 2 possible answers? Binary classification answers yes/no questions, but many real problems have several possible categories: which of 5 flower species is this? Which of 10 handwritten digits is this? Sigmoid alone, giving one probability between 0 and 1, isn't enough — we need one probability per class, and critically, all of those probabilities need to add up to exactly 1 (100%) across all classes.

Video: "Multiclass logistic/softmax regression from scratch"

The Softmax Function Hour 2

Softmax generalizes sigmoid to many classes at once. Instead of computing one linear combination and squashing it with sigmoid, the model computes one linear combination per class, then the softmax function converts that whole set of numbers into a proper probability distribution — every value between 0 and 1, and the whole set summing to exactly 1.

softmax(z_i) = e^(z_i) / Σ e^(z_j)   # for every class j

import numpy as np

def softmax(z):
    exp_z = np.exp(z - np.max(z))   # subtracting max first for numerical stability
    return exp_z / np.sum(exp_z)

class_scores = np.array([2.0, 1.0, 0.1])   # raw linear output, one number per class
probabilities = softmax(class_scores)
print(probabilities)   # e.g. [0.66 0.24 0.10] — sums to 1.0
print(np.argmax(probabilities))   # the predicted class — the one with highest probability
Connecting back to Week 3 Notice np.argmax reappearing from Week 3's NumPy work — exactly the same "give me the position of the largest value" idea, now used to pick the model's final predicted class from a list of probabilities.

One-Hot Encoding the Labels Hour 3

To compare the model's predicted probabilities against the true class during training, the true label also needs to be represented as a probability-shaped vector — this is called one-hot encoding: a vector of all zeros except a single 1 in the position of the correct class.

# 3 classes: 0=setosa, 1=versicolor, 2=virginica
# a flower that is actually class 1 (versicolor) becomes:
one_hot = np.array([0, 1, 0])

# the model's cost function (categorical cross-entropy — the multiclass
# generalization of Day 3's log loss) compares this to the predicted [0.24, 0.66, 0.10]
Common beginner confusion One-hot encoding is a labeling trick for training, not something you'd do to a truly ordinal category — remember Week 2's nominal vs. ordinal distinction: one-hot encoding is exactly the safe way to represent nominal categories (with no natural order) numerically, avoiding the false-order trap discussed back in Week 2, Day 4.

Putting It Together — Using scikit-learn Hour 4

Now that you understand exactly what's happening inside, here's the same multiclass Logistic Regression using scikit-learn, the library you'll rely on heavily going forward:

from sklearn.linear_model import LogisticRegression
from sklearn.datasets import load_iris

data = load_iris()
X, y = data.data, data.target   # 3 flower species, 4 features each

model = LogisticRegression(max_iter=200)
model.fit(X, y)                  # internally: softmax + gradient-based training, just like above

print(model.predict(X[:5]))       # predicted class for the first 5 flowers
print(model.predict_proba(X[:5])) # the full softmax probability distribution for each

Code Practice — Consolidating the Week

Hour 1–4 · Hands-on practice across all four algorithms, using scikit-learn

Why a Whole Day of Just Practice? Hour 1–4

You've now met four closely related algorithms in four days — Multivariate Linear Regression, Polynomial Regression, Binary Logistic Regression, and Multiclass Logistic Regression. Today has no new theory; the goal is pure repetition and comparison, using scikit-learn's consistent interface, so the pattern common to all of them becomes second nature: every scikit-learn model follows the same .fit() / .predict() shape, no matter which specific algorithm is underneath.

from sklearn.linear_model import LinearRegression, LogisticRegression
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.model_selection import train_test_split
import numpy as np

# --- 1. Multivariate Linear Regression ---
X_house = np.array([[1200,3,10],[1500,4,5],[800,2,20],[2000,5,2]])
y_price = np.array([250000, 320000, 180000, 410000])

scaler = StandardScaler()               # feature scaling from Day 1
X_scaled = scaler.fit_transform(X_house)

lin_model = LinearRegression()
lin_model.fit(X_scaled, y_price)
print("Linear:", lin_model.predict(X_scaled))

# --- 2. Polynomial Regression ---
x = np.array([1,2,3,4,5]).reshape(-1,1)
y_curved = np.array([2,8,18,32,50])

poly = PolynomialFeatures(degree=2)
X_poly = poly.fit_transform(x)
poly_model = LinearRegression()
poly_model.fit(X_poly, y_curved)
print("Polynomial:", poly_model.predict(X_poly))

# --- 3. Binary Logistic Regression ---
x_study = np.array([1,2,3,4,5,6,7,8]).reshape(-1,1)
y_pass = np.array([0,0,0,0,1,1,1,1])

log_model = LogisticRegression()
log_model.fit(x_study, y_pass)
print("Binary probability:", log_model.predict_proba([[4.5]]))

# --- 4. Multiclass Logistic Regression ---
from sklearn.datasets import load_iris
iris = load_iris()
X_iris, y_iris = iris.data, iris.target
X_train, X_test, y_train, y_test = train_test_split(X_iris, y_iris, test_size=0.2, random_state=42)

multi_model = LogisticRegression(max_iter=200)
multi_model.fit(X_train, y_train)
print("Multiclass accuracy:", multi_model.score(X_test, y_test))
The single biggest takeaway from this week Every algorithm above shares the same four components from Week 4, Day 4: labeled data, a hypothesis, a cost function, and an optimizer. What changes between them is only the shape of the hypothesis (straight line → curve → sigmoid → softmax) and the matching cost function — the training loop's underlying logic barely changes at all. Once this pattern clicks, learning new algorithms for the rest of the course gets significantly faster.

The train_test_split You Just Saw Hour 1–4

Notice the multiclass example split the data into X_train/X_test before training — a small preview of Week 6's Testing & Evaluation material. The idea: never judge a model using the same data it learned from (that's like grading a student's exam using the exact questions they memorized answers to) — always hold out a portion of data the model has never seen, and evaluate on that instead.
