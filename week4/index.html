Combining, Grouping & Plotting with Pandas

Hour 1–4 · Merge/join/concatenation · GroupBy · Discretization & binning · DataFrame operations · Pandas plotting

Merging, Joining & Concatenation Hour 2

The everyday problem this solves. Real data almost never lives in one table. A company might have one table of "Students" (id, name) and a separate table of "Grades" (student_id, score) — and you need to combine them into one table to actually analyze anything. Pandas gives you three related tools for this, and the difference between them matters.

Concatenation — the simplest case: stacking tables on top of each other (or side by side), when they already share the same structure, like combining January's and February's sales records into one long table.

import pandas as pd

jan_sales = pd.DataFrame({"product": ["A", "B"], "sales": [100, 150]})
feb_sales = pd.DataFrame({"product": ["A", "B"], "sales": [120, 130]})

combined = pd.concat([jan_sales, feb_sales], ignore_index=True)
print(combined)   # 4 rows, stacked one after another

Merging / joining — combining two tables sideways, matching rows based on a shared key column (like student_id), the exact same concept as a SQL JOIN if you've ever used a database. The "type" of join controls what happens to rows that don't have a match on both sides:

students = pd.DataFrame({"id": [1, 2, 3], "name": ["Ayesha", "Bilal", "Sara"]})
grades   = pd.DataFrame({"id": [1, 2, 4], "score": [85, 90, 70]})

# inner join — keep ONLY ids present in BOTH tables (id 1, 2)
inner = pd.merge(students, grades, on="id", how="inner")

# left join — keep ALL rows from the left table (students),
# filling in NaN where there's no match in grades (id 3 has no grade)
left = pd.merge(students, grades, on="id", how="left")

# right join — the mirror opposite: keep ALL rows from the right table (grades)
right = pd.merge(students, grades, on="id", how="right")

# outer join — keep EVERY row from BOTH tables, filling NaN wherever there's no match
outer = pd.merge(students, grades, on="id", how="outer")
A simple way to remember the four join types Picture two overlapping circles (a Venn diagram). Inner = only the overlap. Left = everything in the left circle, overlap included. Right = everything in the right circle, overlap included. Outer = both circles entirely, overlap included once.

GroupBy Hour 3–4

The plain-language question GroupBy answers: "break this data into buckets by some category, then summarize each bucket separately." Imagine sorting a pile of receipts into separate envelopes by store name, then adding up the total for each envelope — that's exactly what GroupBy automates.

sales = pd.DataFrame({
    "region": ["North", "South", "North", "South", "North"],
    "amount": [100, 200, 150, 250, 130]
})

grouped = sales.groupby("region")["amount"].sum()
print(grouped)
# North    380
# South    450

# multiple summaries at once
summary = sales.groupby("region")["amount"].agg(["mean", "sum", "count"])
print(summary)
Why this matters constantly "Average sales per region," "count of customers per city," "total revenue per month" — an enormous fraction of real business analytics questions are answered with one GroupBy call. It is arguably the single most important Pandas method to feel fully comfortable with.

Discretization and Binning Hour 3–4

The idea. Sometimes a continuous number (Week 2's vocabulary) is more useful summarized into a small number of categories — turning an exact age like 34 into the bucket "30–39," for instance. This process is called binning or discretization, and it's often used to simplify a chart or a model.

ages = pd.Series([5, 17, 25, 40, 62, 80])

bins = [0, 18, 35, 60, 100]
labels = ["Child", "Young Adult", "Adult", "Senior"]

age_groups = pd.cut(ages, bins=bins, labels=labels)
print(age_groups)
# 0          Child
# 1    Young Adult
# 2    Young Adult
# 3          Adult
# 4         Senior
# 5         Senior

Pandas for Plotting Hour 3–4

Pandas includes basic, quick charting built directly into every DataFrame and Series — a fast way to eyeball your data before reaching for a more powerful library like Seaborn tomorrow. All of these are one-liners: .plot(kind="...").

import matplotlib.pyplot as plt

sales.plot(kind="bar", x="region", y="amount")     # bar chart
sales["amount"].plot(kind="hist")                    # histogram
sales["amount"].plot(kind="line")                     # line chart
sales.plot(kind="scatter", x="region".__len__(), y="amount")  # (scatter needs 2 numeric columns)
sales["amount"].plot(kind="density")                  # smoothed distribution curve
sales["amount"].plot(kind="box")                       # box plot — quartiles & outliers from Week 2
sales["amount"].plot(kind="kde")                       # kernel density estimate — a smoother histogram
sales.groupby("region")["amount"].sum().plot(kind="pie")  # pie chart of grouped totals
sales.plot(kind="barh", x="region", y="amount")        # horizontal bar chart
sales["amount"].plot(kind="hexbin", x="amount", y="amount", gridsize=10)  # density in hex bins (2 numeric cols)
plt.show()
Note scatter and hexbin both require two genuinely separate numeric columns to be meaningful — the line above showing x="region".__len__() is illustrative only; in practice you'd plot two real numeric columns like sales.plot(kind="scatter", x="units_sold", y="amount").

Seaborn — Statistical Visualization

Hour 1–4 · Intro to Seaborn · Distribution plots · Categorical data plots · Matrix plots

Introduction to Seaborn Hour 1

Why not just use Pandas plotting from yesterday? Pandas' built-in .plot() is great for a fast peek, but it's basic. Seaborn is a charting library built on top of matplotlib, specifically designed for statistical graphics — it understands DataFrames natively, adds attractive default styling, and makes genuinely hard chart types (like a correlation heatmap or a violin plot) a single line of code.

import seaborn as sns
import matplotlib.pyplot as plt

sns.set_theme()   # apply Seaborn's nicer default visual style

Distribution Plots Hour 2

These answer: "what does the shape of this one column's values look like?" — the visual companion to Week 2's mean/median/mode and Week 3's normal distribution.

tips = sns.load_dataset("tips")   # a built-in sample dataset of restaurant bills

# distplot / histplot — histogram + smoothed curve of one column's distribution
sns.histplot(tips["total_bill"], kde=True)
plt.show()

# kdeplot — JUST the smoothed curve, no bars — good for comparing shapes cleanly
sns.kdeplot(tips["total_bill"])
plt.show()

# rugplot — tiny tick marks along the axis showing exactly where each data point sits
sns.rugplot(tips["total_bill"])
plt.show()

# jointplot — combines a bivariate scatter plot with each variable's own distribution on the sides
sns.jointplot(data=tips, x="total_bill", y="tip", kind="scatter")
plt.show()

# pairplot — every pair of numeric columns plotted against every other, all at once
sns.pairplot(tips)
plt.show()
Beginner tip A pairplot is a fantastic first move on any new dataset — one line instantly shows you the relationship (and correlation, from Week 3) between every pair of numeric columns at once, saving you from writing a dozen individual scatter plots by hand.

Categorical Data Plots Hour 3

These are designed specifically for comparing a numeric value across categories — connecting directly back to Week 2's nominal/ordinal categorical data types.

# boxplot — shows median, quartiles, and outliers (Week 2's Measures of Position) per category
sns.boxplot(data=tips, x="day", y="total_bill")
plt.show()

# violinplot — like a box plot, but also shows the full shape of the distribution
sns.violinplot(data=tips, x="day", y="total_bill")
plt.show()

# stripplot — every individual data point plotted, slightly jittered so points don't overlap
sns.stripplot(data=tips, x="day", y="total_bill")
plt.show()

# swarmplot — like stripplot, but arranges points so none overlap at all
sns.swarmplot(data=tips, x="day", y="total_bill")
plt.show()

# barplot — shows the mean of a numeric column per category, with a confidence interval
sns.barplot(data=tips, x="day", y="total_bill")
plt.show()

# countplot — simply counts how many rows fall into each category (no numeric column needed)
sns.countplot(data=tips, x="day")
plt.show()

# factorplot / catplot — a flexible, general-purpose wrapper for ALL of the plots above,
# selected via the kind= argument
sns.catplot(data=tips, x="day", y="total_bill", kind="box")
plt.show()
Choosing between them Use countplot when you just want frequencies. Use barplot when you want a mean comparison. Use boxplot or violinplot when the full spread and outliers matter, not just the average.

Matrix Plots — Heatmap Hour 4

A heatmap displays a 2D grid of numbers as colors — darker or brighter shading representing higher or lower values — making patterns across a large table instantly visible without reading a single number. Its single most common use in data science: visualizing a correlation matrix, extending Week 3's single correlation coefficient to every pair of columns at once.

numeric_cols = tips[["total_bill", "tip", "size"]]
correlation_matrix = numeric_cols.corr()

sns.heatmap(correlation_matrix, annot=True, cmap="coolwarm")
plt.show()
Reading a correlation heatmap annot=True prints the actual correlation number inside each cell. Look for cells close to +1 (strong positive, often shown in one color) or −1 (strong negative, shown in the opposite color) — those are the variable pairs most worth investigating further, exactly the multivariate analysis previewed back in Week 3, Day 1.

Introduction to Machine Learning

Hour 1–4 · What ML is & its types · The classical machine learning pipeline

What Is Machine Learning, Really? Hour 1

The plain-language definition. Traditional programming is: a human writes explicit rules ("if temperature > 30, say 'hot'"), and the computer follows them exactly. Machine Learning flips this around: instead of a human writing the rules, you show the computer many examples of inputs and correct answers, and the computer figures out the rule (or pattern) itself. You don't tell it "spam emails usually contain the word 'free'" — you show it 10,000 emails already labeled spam/not-spam, and it learns which patterns matter on its own.

Why this shift matters. Some problems are simply too complex for a human to write exhaustive rules for — recognizing a face in a photo, translating a sentence, predicting which customers will cancel a subscription. These problems have patterns, but the patterns are too subtle, high-dimensional, or numerous for a person to hand-code. ML lets the computer discover those patterns directly from data.

The Three Main Types of Machine Learning Hour 1

  • Supervised Learning — you have labeled examples (input + correct answer already known), and the model learns to predict the answer for new, unseen inputs. Analogy: a student learning from a textbook with an answer key. This is the category you'll focus on for the next several weeks.
  • Unsupervised Learning — you have data with no labeled correct answers, and the model finds hidden structure or groupings on its own (e.g. automatically clustering customers into similar segments). Analogy: sorting a box of mixed items into natural groups without being told the categories in advance.
  • Reinforcement Learning — an agent learns by trial and error, taking actions in an environment and receiving rewards or penalties, gradually learning a strategy that maximizes reward over time. Analogy: training a dog with treats — no one tells the dog the exact rule, but it learns which behaviors get rewarded.
Where this course focuses Weeks 5–6 dive deep into Supervised Learning; Week 6 also touches Unsupervised methods. Deep Learning (Weeks 7–9) mostly builds supervised and sequence-based models on top of neural networks. Reinforcement Learning is mentioned for completeness but isn't a major focus of this curriculum.

The Classical Machine Learning Pipeline Hour 2–4

Building an ML system is never just "run one algorithm" — it's a sequence of stages, and real-world projects typically spend far more time on the early stages than on the model itself. This exact sequence will structure how you approach every project for the rest of the course:

  1. Data collection — gathering the raw data you'll learn from: surveys, sensors, databases, scraped web pages, public datasets. The quality and relevance of this stage caps how good everything downstream can possibly be ("garbage in, garbage out").
  2. Preprocessing — cleaning the raw data: handling missing values (Week 3, Day 5!), removing duplicates, fixing inconsistent formatting, and encoding categorical variables (Week 2's nominal/ordinal data) into a form a model can use.
  3. Feature crafting (feature engineering) — deciding which columns ("features") the model should actually look at, and sometimes creating brand-new, more useful columns from the raw ones (e.g. turning a birthdate into "age," which is usually far more predictive on its own).
  4. Modeling — choosing and training an algorithm (like the Linear Regression you'll build by hand later this week) on the prepared data, so it learns the underlying pattern.
  5. Testing and evaluation — checking how well the trained model performs on data it has never seen before, using metrics appropriate to the problem, so you know whether to trust it.
  6. Deployment — putting the finished, evaluated model into a real application where it makes live predictions for real users, and then monitoring it over time as real-world data changes.
Common mistake beginners make Jumping straight to "modeling" and skipping careful preprocessing and evaluation. A sophisticated model trained on messy, unvalidated data will confidently produce wrong answers — the pipeline's earlier and later stages matter just as much as the algorithm itself.

Supervised Machine Learning

Hour 1–4 · Regression vs. classification · Components of supervised learning · Intro to Linear Regression

Regression vs. Classification Problems Hour 1–2

Supervised learning splits into two problem types, distinguished by one simple question: "is the answer a number, or a category?"

  • Regression — predicting a continuous numeric value (Week 2's vocabulary again!): house price, temperature tomorrow, a student's exam score. The possible outputs form a smooth range.
  • Classification — predicting a category from a fixed, discrete set of options: spam or not-spam (binary), which of five species a flower belongs to (multi-class). The output is always one label from a known list.
Quick test you can apply yourself Ask: "could the answer sensibly be any number, including a decimal?" If yes → regression (house price: $342,150.75 makes sense). If the answer must be one of a fixed set of labels → classification (species: "setosa," never "setosa.3").

Components of Supervised Machine Learning Hour 1–2

Every supervised learning system, no matter how complex, is built from the same four core pieces. Understanding these four terms deeply is worth more than memorizing any specific algorithm — they reappear, renamed slightly, in every model for the rest of this course.

  • Labeled data — your training examples, each one a pair of (input features, correct answer). E.g. (house size, number of bedrooms) → actual sale price.
  • Hypothesis — the model's current "best guess" function for mapping inputs to outputs; literally the mathematical formula the model is trying to tune to fit the data.
  • Cost function (loss function) — a single number measuring "how wrong is the hypothesis right now, across all the training examples?" Training a model means searching for the hypothesis that makes this number as small as possible.
  • Optimizer — the algorithm that actually adjusts the hypothesis, step by step, to reduce the cost function. Gradient Descent, which you'll implement by hand today and tomorrow, is the classic example.
A single mental model to hold onto Training = "start with a random guess (hypothesis), measure how wrong it is (cost function), then nudge it in the direction that makes it less wrong (optimizer), and repeat thousands of times." This exact loop — guess, measure error, adjust, repeat — is the heartbeat of essentially every ML and Deep Learning algorithm you'll meet in this course.

Univariate Linear Regression — First Look Hour 3–4

The simplest possible regression model. "Univariate" means one input variable. Linear Regression assumes the relationship between that one input (x) and the output (y) can be approximated by a straight line — literally the equation of a line you learned in school:

y = m * x + b
# y = predicted output   x = input feature
# m = slope (how much y changes per unit of x)
# b = intercept (the predicted y when x = 0)

Training this model means finding the specific m and b that make this line fit the training data as closely as possible — exactly the "hypothesis" from above, with only two numbers to tune. Tomorrow, you'll implement the full training loop by hand, without any ML library, so you truly understand what's happening before you ever call model.fit() in scikit-learn.

Linear Regression with Gradient Descent

Hour 1–4 · Gradient Descent without vectorization · Gradient Descent with vectorization

Gradient Descent — The Everyday Intuition Hour 1–2

Before any math: an analogy. Imagine standing on a foggy hillside at night, trying to reach the lowest point in a valley, but you can only see the ground right under your feet. A sensible strategy: feel which direction slopes downward, take a small step that way, and repeat. Eventually, step by step, you reach the bottom. Gradient Descent is exactly this strategy, applied to the cost function from yesterday: the "hillside" is a graph of "how wrong is this m and b," and the "bottom of the valley" is the combination of m and b that makes the model as accurate as possible.

The cost function for Linear Regression — Mean Squared Error (MSE) — measures how wrong the current line is, on average, across every training point:

Cost(m, b) = (1/n) * Σ (predicted_y - actual_y)²
# for each point: how far off was the prediction, squared (so errors can't cancel out —
# the exact same reasoning you learned for Variance back in Week 2), then averaged over all n points

The "gradient" is just the slope of that cost function with respect to m and b — it tells you exactly which direction to nudge each one to reduce the error. The "descent" is repeatedly stepping in that downhill direction, controlled by a learning rate (how big each step is — too large and you overshoot the bottom; too small and training takes forever).

Implementing Gradient Descent Without Vectorization Hour 1–2

Let's build it from scratch, using plain Python loops (Week 1 skills) so every single step is visible — no shortcuts, no libraries hiding the mechanics:

# training data: hours studied -> exam score
x = [1, 2, 3, 4, 5]
y = [52, 58, 65, 70, 78]

m = 0.0     # start with a random/zero guess for slope
b = 0.0     # start with a random/zero guess for intercept
learning_rate = 0.01
epochs = 1000     # number of times we'll repeat the "step downhill" process
n = len(x)

for epoch in range(epochs):
    m_gradient = 0.0
    b_gradient = 0.0

    # loop over every single training point, one at a time — no vectorization
    for i in range(n):
        prediction = m * x[i] + b
        error = prediction - y[i]
        m_gradient += (2/n) * error * x[i]     # how much this point pulls the slope
        b_gradient += (2/n) * error              # how much this point pulls the intercept

    # take a small step downhill for BOTH m and b
    m = m - learning_rate * m_gradient
    b = b - learning_rate * b_gradient

    if epoch % 200 == 0:
        print(f"Epoch {epoch}: m={m:.3f}, b={b:.3f}")

print(f"Final model: y = {m:.2f}x + {b:.2f}")
Why this version is slow Notice the inner for i in range(n): loop — for every single one of the 1,000 epochs, we loop through every training point one at a time in pure Python. With 5 points this is instant; with 5 million points (a realistic dataset size), this becomes painfully slow, because Python loops are far slower than NumPy's vectorized operations from Week 3.

Implementing Gradient Descent With Vectorization Hour 3–4

The upgrade. "Vectorization" means replacing that inner Python loop with NumPy array operations that process every training point at once — exactly the broadcasting and element-wise arithmetic you practiced in Week 3. Same algorithm, same math, dramatically faster execution:

import numpy as np

x = np.array([1, 2, 3, 4, 5])
y = np.array([52, 58, 65, 70, 78])

m, b = 0.0, 0.0
learning_rate = 0.01
epochs = 1000
n = len(x)

for epoch in range(epochs):
    predictions = m * x + b              # ALL predictions at once — no inner loop
    errors = predictions - y              # ALL errors at once

    m_gradient = (2/n) * np.sum(errors * x)   # one vectorized sum instead of a manual loop
    b_gradient = (2/n) * np.sum(errors)

    m = m - learning_rate * m_gradient
    b = b - learning_rate * b_gradient

    if epoch % 200 == 0:
        cost = np.mean(errors ** 2)
        print(f"Epoch {epoch}: m={m:.3f}, b={b:.3f}, cost={cost:.3f}")

print(f"Final model: y = {m:.2f}x + {b:.2f}")

# making a prediction with the trained model
def predict(hours_studied):
    return m * hours_studied + b

print(predict(6))   # estimated exam score for 6 hours of studying
The key insight to take away Both versions above compute the exact same mathematics and reach the exact same final m and b — vectorization is purely a performance optimization, not a different algorithm. This is precisely why Week 3's NumPy skills exist: every real ML and Deep Learning library (scikit-learn, TensorFlow, PyTorch) is vectorized under the hood for exactly this reason.
